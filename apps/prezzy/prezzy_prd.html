PREZZY VISÃO · PROBLEMA · OPORTUNIDADE
Visão do Produto

Prezzy é o único gerador de apresentações e eBooks que usa um pipeline de IA multi-agente para pesquisar, estruturar, escrever e renderizar documentos profissionais — exportáveis em qualquer resolução de tela, de A4 a painéis de LED.

O Problema

Tempo Desperdiçado

Profissionais gastam 4–8 horas montando apresentações que poderiam ser geradas em 90 segundos. O Canva faz o design mas não gera o conteúdo.

Ferramentas Fragmentadas

ChatGPT escreve, Canva diagramou, Gamma tenta os dois — mas nenhum exporta PDF de qualidade editorial, muito menos em resolução customizada.

Resolução Padrão Única

Todas as ferramentas assumem 16:9. Igrejas, feiras, painéis de LED, totens — ninguém serve essas resoluções exóticas como 1536×512.

Vendor Lock-in de IA

Ferramentas travam você num único modelo. Quando a API cai ou o preço sobe, você fica refém. Multi-provider é sobrevivência.

Agente 4 · Designer

Escolhe template, paleta e tipografia. Injeta conteúdo no HTML do Gabarito V4. Aplica resolução custom via CSS. Gera arquivo final.

Sistema Multi-Key com Rotation e Fallback

O Superuser cadastra múltiplas API Keys por provedor no painel admin. O sistema rotaciona entre elas automaticamente (round-robin) e detecta rate-limits ou erros 429 para pular para a próxima key sem interromper a geração do usuário.

Key Rotation

Cadastra N keys por provedor. O sistema distribui as chamadas ciclicamente. Se uma key atinge limite, pula para a próxima automaticamente.

Provider Fallback

Se o Groq cair, cai para Gemini. Se o Gemini estiver lento, tenta OpenRouter. Ordem de fallback configurável pelo admin no painel.

Painel de API Keys (Admin)
  • Adicionar / remover keys por provedor sem restart do servidor
  • Ver status de cada key (ativa / rate-limited / inválida)
  • Consumo estimado por key (tokens usados hoje)
  • Definir provedor padrão por tipo de agente (ex: Groq para pesquisa, GPT para copy)
  • Modo "gratuito total" — usa só as keys do admin para os usuários Free

Sprint 1 · Semanas 1–2 · Core Pipeline

  • FastAPI com endpoint /generate recebendo JSON do wizard
  • 4 agentes Groq encadeados (pesquisa → estrutura → copy → design)
  • Gabarito V4 injetado como template base + Playwright → PDF
  • Upload para Supabase Storage + retorno de URL

Sprint 2 · Semanas 3–4 · Frontend + Auth

  • Next.js wizard 7 etapas com preview do template selecionado
  • Supabase Auth (login, convite por email, roles)
  • Painel Superuser: criar contas Free, ver uso, gerenciar API keys
  • Sistema de créditos + limite por role

Sprint 3 · Semanas 5–6 · Multi-Provider + Custom Resolution

  • Integração Gemini, GPT-4o, OpenRouter com fallback automático
  • Multi-key rotation com painel de status das keys
  • Custom resolution: Playwright renderiza em WxH arbitrário
  • Preset de painéis (1536×512, 16:9, 9:16, A4)
